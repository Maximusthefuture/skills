# Профили агентов

Профиль добавляет готовые инструкции роли к следующей сессии runner-а. Его можно выбрать при создании агента или изменить в карточке существующего.

| Профиль | Когда выбирать |
| --- | --- |
| Аналитик | Уточнение требований, выявление неоднозначностей, подготовка спецификации по заданию. |
| Разработчик | Реализация согласованного поведения и проверка результата. |
| Ревьюер | Независимая проверка реализации с замечаниями, подтверждёнными кодом или тестами. |

## Создать агента с профилем

1. Откройте вкладку **«Агенты»**.
2. Раскройте **«Новый агент из шаблона»**.
3. Укажите уникальное имя, выберите шаблон CLI и модель. Вариант **«из шаблона»** использует модель выбранного шаблона.
4. Выберите **«Профиль роли»** и нажмите **«Добавить агента»**.

Агент появится остановленным. Запускайте его отдельно, когда команда и задача подготовлены.

## Изменить или отключить профиль

В карточке агента нажмите **«Раскрыть»**, выберите профиль и нажмите **«Применить профиль»**. Выбор сохраняется в конфигурации проекта.

Новая роль применяется со следующей сессии. Смена профиля не прерывает текущую сессию и не запускает остановленного агента. Для отключения выберите **«Без профиля»** и примените изменение.

В блоке **«Инструкции профиля»** можно прочитать текст, который получает агент. Поле **«Файл инструкций»** позволяет добавить правила конкретного проекта: они дополняют готовый профиль.

## Как профиль связан с моделью и инструментами

Профиль отвечает за инструкции роли. Модель выбирается отдельным полем; доступные инструменты и права определяются настройками CLI. Профиль ревьюера сам по себе не обеспечивает режим только для чтения.

Все роли соблюдают постановку задачи, владение файлами и утверждённые решения. Аналитик пишет спецификацию, когда это требуется заданием; ревьюер меняет файлы только при явном поручении в своей области ответственности.

Профиль не определяет ведущего задачи. Ведущим становится первый агент выбранной команды согласно обычному протоколу проекта.

## Координатор

Сейчас координатор предлагает команду из ID уже настроенных runner-ов. Новые профили ещё не передаются ему для автоматического подбора ролей. Не следует рассчитывать, что назначение профиля само изменит состав команды, создаст или запустит дополнительных агентов.

Подбор по ролям можно добавить отдельно: передавать координатору ID и профиль каждого доступного агента, затем проверять предложенную команду перед подтверждением задачи.

## Настройка в runners.json

Поле `profile` можно задавать в агенте, `defaults` или шаблоне CLI. Значения: `analyst`, `developer`, `reviewer`.

Фрагмент существующей конфигурации, в которой команды CLI и модели уже заданы:

```json
{
  "agents": [
    { "id": "analyst", "profile": "analyst" },
    { "id": "developer", "profile": "developer" },
    { "id": "reviewer", "profile": "reviewer" }
  ]
}
```

Агент наследует профиль из `defaults`, если собственного значения нет. `"profile": null` явно отключает наследование. Старые конфигурации без поля `profile` продолжают работать с существующими инструкциями.
