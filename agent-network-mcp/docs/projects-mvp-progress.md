# Projects MVP: состояние реализации

Исходный объём и пользовательские критерии: [projects-mvp-plan.md](projects-mvp-plan.md). Документ фиксирует состояние кода отдельно от сквозной приёмки.

## Реализовано

- Постоянный `projectId`, ProjectStore, сообщения и очередь, сохранение паузы, сериализованный claim одного Coordinator, отмена, замена queued сообщения и восстановление orphan run.
- Изолированный Claude/Kimi CLI executor с отдельной временной папкой, ограниченным набором project MCP tools и отключёнными shell/coding tools и hooks. Executor запускается только для queued run; сам по себе idle не обращается к модели.
- Project MCP чтения истории, памяти, связанных задач и предложений; создания task proposal и memory proposal. Запись ограничена активным авторизованным run, proposal требует отдельного решения пользователя.
- Серверная нормализация и hash effective payload, preflight, revise/supersedes, approve/reject, лимиты и повторная проверка перед созданием. Создание Task выполняется через существующий operator service и идемпотентный operation journal.
- Явное подключение/отключение задач, адресный follow-up с подтверждением точного текста, восстановление связи задачи с проектом после повторного запроса.
- `from`: finalization артефактов через manifest/hash, восстановление незавершённой операции и исключение задачи с незавершённым input из runner selection.
- Память с immutable proposals, `baseHash`, отдельным подтверждением и восстановлением materialization. Retry сверяет операции и передаёт сохранённые предложения/результаты исполнителю; повторный run не может записывать новые task или memory proposals.
- Bounded snapshot и пагинация истории и task context (до 16 KiB на страницу), проверка membership, чтение вопросов/ответов, результатов integration, acceptance evidence и sync findings.
- UI `/project`: история, черновик, очередь, пауза, отмена, retry, статусы runs, proposals с деталями/preflight/редактированием/решениями, память, связанные задачи и заметные статусы ожидания со ссылками на карточку задачи. Polling сохраняет ввод, прокрутку и фокус.
- README содержит пользовательское описание, настройку Coordinator и границы модели/приёмки.

## Проверки без реальных моделей

- `npm run build` — прошёл.
- `npm run typecheck` — прошёл.
- Проектные unit-тесты с подменённым executor — 22 файла, 35 тестов прошли; реальные модели не вызывались.
- Реальные Claude/Kimi модели в этой доработке не запускались по указанию пользователя.
- Сквозной пользовательский прогон UI, клавиатуры, двух вкладок и перезапуска в работающем приложении не проводился; наличие кода и успешная сборка не подтверждают эти UX-критерии.

## Осталось для приёмки

1. Провести ручной UX-прогон UI и гонок/перезапуска без обращения к модели, используя подменённый executor.
2. Отдельно проверить совместимость конфигурации с установленными Claude/Kimi CLI, если пользователь решит разрешить реальный запуск.
3. Сопоставить полный регрессионный прогон проекта с известными Windows-зависимыми сбоями и разобрать актуальные ошибки.

Реальные модели не требуются для локальной проверки серверных механизмов и UI. До ручной приёмки нельзя утверждать, что весь MVP проверен сквозным пользовательским сценарием.
