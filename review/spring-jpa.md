# Spring и JPA/Hibernate

## Транзакции
- **Self-invocation**: вызов `@Transactional`/`@Async`/`@Cacheable`/`@Retryable` метода из того же класса идёт мимо прокси — аннотация не работает.
- `@Transactional` на `private`/`final` методах или `final` классе — не проксируется.
- Откат по умолчанию только для `RuntimeException` и `Error`: checked-исключение коммитит транзакцию, если нет `rollbackFor`.
- Пойманное и проглоченное внутри транзакции исключение после `UnexpectedRollbackException` от вложенного вызова с `REQUIRED`.
- Внешние вызовы (HTTP, Kafka, почта) внутри транзакции: долгие блокировки, и событие уходит, даже если транзакция потом откатится. Ищи `@TransactionalEventListener(phase = AFTER_COMMIT)` или outbox.
- `readOnly = true` на методах, которые пишут; отсутствие транзакции у метода, который делает несколько связанных записей.
- `REQUIRES_NEW` в цикле или с тем же ресурсом, что держит внешняя транзакция (дедлок, исчерпание пула).

## JPA / Hibernate
- **N+1**: обход lazy-коллекции в цикле или в маппере DTO. Нужен `JOIN FETCH`, `@EntityGraph` или проекция.
- `LazyInitializationException`: доступ к lazy-связи вне транзакции (в контроллере, после возврата из сервиса, в `toString`/Jackson). `spring.jpa.open-in-view=true` маскирует это — проверь, не опирается ли код на OSIV.
- `FetchType.EAGER` на `@OneToMany`/`@ManyToMany`; `@ManyToOne` по умолчанию EAGER.
- `JOIN FETCH` коллекции + пагинация → пагинация в памяти (предупреждение HHH90003004).
- Сущность возвращается из REST напрямую вместо DTO (утечка полей, рекурсия, lazy-загрузки).
- Изменение managed-сущности без `save` всё равно запишется (dirty checking) — непреднамеренные апдейты; и наоборот, ожидание, что `save` detached-сущности не перетрёт поля.
- `saveAll`/`deleteAll` по одной строке на больших объёмах; отсутствие batch-настроек при массовых вставках; `IDENTITY` отключает batch insert.
- Нет `@Version` там, где возможны конкурентные обновления (потерянные апдейты); пессимистичные блокировки без таймаута.
- Нативные запросы и JPQL со строковой конкатенацией (см. security.md).
- `equals`/`hashCode` сущностей — см. java-core.md.

## Миграции (Flyway / Liquibase)
- Изменён уже применённый скрипт миграции (сломает checksum на окружениях).
- `NOT NULL` колонка без default на существующей таблице; переименование/удаление колонки, которую читает ещё работающая старая версия приложения (нужен expand/contract).
- Индекс на большой таблице без `CONCURRENTLY` (PostgreSQL) — блокировка записи.
- Изменения в сущности без соответствующей миграции (или `ddl-auto=update` в проде).

## Бины и конфигурация
- Field injection (`@Autowired` на поле) там, где проект требует constructor injection; циклические зависимости.
- Изменяемое состояние в singleton (см. java-core.md); prototype-бин, внедрённый в singleton, ожидаемо «новый» каждый раз.
- `@Value` без default для необязательных свойств; новое свойство не добавлено в `application.yml`/профили; секреты в `application.yml` в репозитории.
- `@ConfigurationProperties` без `@Validated`, если значения критичны.
- `@Scheduled` в нескольких инстансах без распределённой блокировки (ShedLock) — задача выполнится N раз.
- `@EventListener` синхронный и бросает исключение — откатывает транзакцию публикующего.

## Web / REST
- Нет `@Valid` на `@RequestBody`, хотя DTO аннотирован ограничениями; валидация вложенных объектов без `@Valid` на поле.
- Неправильные коды ответа (200 на создание вместо 201, 500 вместо 4xx для ошибок клиента); исключения без маппинга в `@ControllerAdvice`.
- Ломающее изменение контракта: переименование/удаление поля DTO, смена типа, новое обязательное поле в запросе, изменение формата дат, enum без обработки неизвестных значений у потребителей.
- Пагинация без верхней границы размера страницы; эндпоинты, возвращающие всю таблицу.
- `RestTemplate`/`WebClient` без таймаутов; повторные попытки неидемпотентных операций.

## Кэш
- `@Cacheable` с ключом, не учитывающим все параметры, влияющие на результат (в т.ч. пользователя/тенанта).
- Кэширование изменяемых объектов или JPA-сущностей; нет инвалидации при записи.

- Смешение `javax.*` и `jakarta.*`; устаревший `WebSecurityConfigurerAdapter`; изменения в `spring.factories` → `AutoConfiguration.imports`.
