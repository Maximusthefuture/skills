# Java conventions

Three rules for every Java change. The project's `CLAUDE.md` and existing code win when they differ — follow the project and say so in the report.

## 1. Packages by layer

Under the root package, one level, a package appears with its first class:

```
controller/  implements a generated *Api; no logic, no @Transactional
service/     business logic, transactions; maps entity → DTO via mapper/
repository/  Spring Data
entity/      @Entity and the enums they persist
mapper/      entity ↔ generated DTO
config/      @Configuration, @ConfigurationProperties
exception/   exceptions + @RestControllerAdvice
client/      calls to external HTTP/gRPC systems
listener/    Kafka/Rabbit consumers, @EventListener — parse and call a service
producer/    Kafka/Rabbit senders, outbox relay
scheduler/   @Scheduled — call a service
dto/         DTOs and event payloads that are NOT in the OpenAPI spec
util/        final class, static pure functions, no Spring, no business rules
```

`controller → service → repository`, never back and never skipping a layer. The service returns DTOs mapped inside its transaction, so lazy associations are read while the session is open. A class that fits nowhere usually does two jobs — split it. Naming, sub-packages, test doubles: [references/project-structure.md](references/project-structure.md) — only if the tree above does not answer.

## 2. API: spec → generated interface → @Override

1. Edit the spec (path from `<inputSpec>` in `pom.xml` / `build.gradle`), with an `operationId` and `$ref` schemas.
2. Generate: `./mvnw -q generate-sources` / `./gradlew openApiGenerate`; take the method signature from the generated `*Api` in `target/generated-sources/openapi` (`build/generate-resources`).
3. Implement it in the controller with `@Override`; one controller per interface, `OrdersApi` → `OrdersController`.
4. Check every new operation has an `@Override`: generated methods are `default` returning 501, so a forgotten one compiles.

Not allowed: `@GetMapping`/`@PostMapping` or `@RequestMapping` on the controller, repeating `@PathVariable`/`@RequestBody`/`@Valid` on the implementation, hand-written copies of generated models, edits of generated files. A changed or removed field, type or `required` breaks clients — say so in the report.

Generation cannot run, a new tag, a model/entity name clash, an old controller without an interface, an endpoint the user wants outside the spec: [references/openapi-workflow.md](references/openapi-workflow.md).

## 3. Comments — in Russian, by default none

- **Line comment** — only *why* the code cannot say: an outside rule, a constraint, a workaround, an order that matters. **≤ 5 words** (a ticket key does not count). Unclear *what* → rename or extract a method instead.
- **Javadoc on a class or method** — first decide if it is needed: the name, package and signature usually say it. Needed for an invariant, a boundary, thread-safety, a hidden contract (returns `null`, side effect, which exception). **≤ 20 words**, no retelling of the name.
- **Never:** comments that restate code, `@param id идентификатор`, dividers (`// ===== поля =====`), `@author`/`@since`, commented-out code, `TODO` without a ticket.
- Untouched code keeps its comments; a comment your change made false — fix or remove.

```java
// получаем заказ              ← нет: пересказ кода
// банк отклоняет суммы ниже 10 ← да: причина
```

Before finishing, run `python3 <this-skill>/scripts/check_comments.py` (uncommitted changes and new files; or pass a range like `main...HEAD`, or `--files A.java`) and fix what it flags.

Report deviations only: a class outside the tree, an endpoint outside the spec, a contract break.
